## Contents
- `internal/api/apierr` (tiny shared package): the one error shape `{"error":{"code","message"}}` with `Write(w, status, code, message)` and the code constants, so auth and the API handlers agree.
- Passwords (AUTH-7): argon2id with a random 16-byte salt and parameters encoded in a PHC-format string; constant-time verify; minimum 12 characters; reject a new password equal to the current one.
- Local admin (AUTH-7, AUTH-8, rules list): `EnsureLocalAdmin(ctx, store, initialPassword string, log)` creates, only if absent, the user `admin` (`auth_source=local`, role `admin`, status active, `must_change_password=true`) with the given password, or a generated 24-character one printed exactly once to the log at creation. If the row exists the supplied password is ignored. Sign-in is limited to 5 failures per 15 minutes for the account (in memory, sliding window; a success does not clear earlier failures inside the window; while limited, respond `rate_limited` 429 without checking the password). Unknown usernames take the same time as a wrong password and return the same error. The account cannot acquire and has no balance: expose `IsLocalAdmin(user)`.
- Sessions (AUTH-3): 32 random bytes as the cookie value; the `sessions.id` stored is the SHA-256 hex of it. Cookie `hourglass_session`: HttpOnly, Secure, SameSite=Lax, Path=/. Idle timeout 8 hours: `expires_at = last_seen + 8h`, refreshed at most once a minute. CSRF token = hex HMAC-SHA256(session key, session id), returned by the session endpoint and required in `X-CSRF-Token` (constant-time compare) on every request whose method is not GET/HEAD/OPTIONS. The session key comes from config; if empty, generate a random one at start and log that sessions will not survive a restart. Sign-out deletes the row and clears the cookie. A password change deletes the user's other sessions.
- OIDC (AUTH-1, AUTH-2): discovery from the issuer; `GET /auth/oidc/start` redirects with `state`, `nonce` and PKCE S256; those three live in a short-lived (10 min) HttpOnly, Secure, SameSite=Lax cookie authenticated with the session key (no server-side table). `GET /auth/callback` checks state, exchanges the code with the verifier, verifies the ID token (issuer, audience, expiry, nonce), then upserts the user by `sub`: a new user is created with status `pending` and no roles and `user.pending` is emitted; `email` and `name` are refreshed on every sign-in. Creates a session and redirects (302) to `/` (the UI decides what to show). Errors redirect to `/login?error=<code>`; nothing about the failure beyond a code is exposed. Scopes `openid email profile`. When OIDC is not configured the two routes return 404 and `Methods()` reports only local. The UI never sees a token; tokens are not stored.
- `POST /auth/local` `{username, password}`: only the local admin row can sign in this way. `POST /auth/local/password` `{current_password, new_password}`: local admin session + CSRF; clears `must_change_password`. `POST /auth/logout`: any session + CSRF.
- Middleware over `net/http` (stdlib mux): `Authenticate` (loads session and user with roles into the request context; no session leaves it anonymous); `RequireSession` (401 `unauthenticated`); `RequireRole` (any role, else 403 `no_role`; a user whose status is not active or who has no roles gets `no_role`); `RequireAdmin` (403 `forbidden`); `RequireCSRF` (403 `csrf`); and a guard that makes every route except the session endpoint, the password change and logout return 403 `password_change_required` while the local admin has `must_change_password` set. Error responses carry no data. Helpers `UserFrom(ctx)`, `SessionFrom(ctx)`.
- CORS (UI-4): middleware enabling credentialed CORS only for the origins listed in `cors.allowed_origins`; with an empty list no CORS headers are ever sent.
- `Methods()` for `GET /api/v1/auth/methods`: `{oidc: bool, local: true}` and nothing else.
- Secrets (client secret, session key, passwords, cookie values, tokens) never appear in logs or errors.
