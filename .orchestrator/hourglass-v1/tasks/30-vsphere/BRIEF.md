## Design
- One small internal interface, e.g. `type client interface { ResourcePools(ctx) ([]pool, error); Clusters(ctx) ([]clusterFigures, error); Close(ctx) error }`, where `pool` has name, inventory path and parent pool name, and `clusterFigures` has the cluster name, CPU reservationUsed and maxUsage, memory reservationUsed and maxUsage (root resource pool runtime), and the summed capacity and free space of its accessible datastores. All provider and pressure logic is written against this interface; the govmomi implementation is a thin adapter (session login, property collector / container view, re-login once on a not-authenticated fault, logout on Close).
- Config (shared shape for both extensions, so a deployment can give both the same block): `url`, `username`, `password` (falls back to env `HOURGLASS_VSPHERE_PASSWORD` when empty), `insecure_skip_verify` (default false), `datacenter` (optional), `clusters` (list of names; empty means every cluster in scope), `request_timeout` (default 20s). Unknown fields rejected. The password never appears in errors, logs or `String()` output. Provider and pressure source created from equal connection settings share one client/session.
- Provider `List`: one `Allocation` per resource pool within scope, excluding each cluster's hidden root pool ("Resources"). `ResourceName` is the pool's own name (nested pools included, each listed by its own name); labels carry `cluster`, `datacenter`, `parent` and `path`. Read-only: the package must contain no call that creates, changes or destroys anything.
- Pressure (D6): per cluster max(cpu ratio, memory ratio, storage ratio), then the maximum across the configured clusters; each ratio clamped to [0,1]; a zero capacity for CPU or memory is an error; a cluster with no accessible datastore contributes no storage ratio; no clusters found is an error. The pressure source ignores the Snapshot.
## Tests
Layer 2 (hand-written fake of the internal interface; carries all the logic): pool listing and root exclusion; nested pools; duplicate names in different clusters; scope by cluster; every pressure case in D7 (non-zero CPU and memory ratios, max-of-three for each of the three winning, multi-cluster max, values crossing 0.5 / 0.75 / 0.9, zero-capacity error, clamp, inaccessible datastores, no clusters); errors propagate; context cancellation; config parsing, env fallback, secret redaction. Both conformance suites from `pkg/hourglasstest`.
Layer 3 (govmomi simulator in-process, `simulator.VPX()`; test-only code may create pools): create pools named like seeded setups (e.g. `lab-01_RP`, a nested one), assert the provider lists them with the right parent and that destroying one removes it on the next call; pressure returns a value in [0,1] equal (within 1e-9) to the storage ratio computed from the simulator's datastore figures, with CPU and memory ratios 0; TLS: connecting to the simulator's self-signed endpoint fails without `insecure_skip_verify` and works with it; re-login after the session is terminated. These tests must not need the network beyond localhost and must run under `bazel test`.
Names cite EXT-3 / MET-1 / D6 where applicable.
