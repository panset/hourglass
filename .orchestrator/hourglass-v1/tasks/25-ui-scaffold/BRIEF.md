# 25 //ui scaffold: build, API client, app shell
Job intent: .orchestrator/hourglass-v1/INTENT.md (read it first). Rules: .orchestrator/hourglass-v1/CONTRACT.md.
## Goal
The single-page app in `ui/`: React + TypeScript + Vite, built and tested by Bazel with `rules_js`, with a typed API client generated from `api/openapi.yaml`, the application shell, and the two public pages. Later tasks add the six role pages in parallel, so leave a structure in which each page is its own directory and nothing shared needs editing to add one. Spec: docs/SPEC.md UI-1..UI-7, AUTH-5, AUTH-6, "Dashboard pages", "Build, packaging and test environment" (Frontend, Build). Design: `docs/ui-notes.md` (authoritative description of the wireframes: layout, labels, tokens) and the raw artboards in `docs/wireframes/project/` for reference.
## Requirements
- `ui/package.json` (own package, private), Vite, React 18+, TypeScript strict, React Router, a small data-fetching approach without heavy state libraries (plain hooks are fine). Keep dependencies few and permissively licensed (MIT/BSD/Apache-2.0/ISC only). No UI kit that brings its own look: hand-written CSS (CSS modules or one tokens file) following the tokens in docs/ui-notes.md. No fonts or assets loaded from other origins at runtime (bundle or use system fonts).
- Bazel: `rules_js` (and `rules_ts` if useful) via bzlmod in `MODULE.bazel` with a pinned Node toolchain and a committed lockfile (`pnpm-lock.yaml`; pnpm is not installed here, use `npx --yes pnpm@<pinned>` to produce it). Targets: `//ui:dist` (the production build as a directory/tree artifact, to be embedded by a later task), `//ui:test` (unit tests with Vitest + Testing Library, jsdom), `//ui:typecheck`. `bazel build //...` and `bazel test //...` must stay green and hermetic (no network at test time). Add `ui` handling to `.bazelignore`/gazelle excludes as needed (`node_modules`). You own MODULE.bazel for this task; do not change Go-related entries.
- API client: types generated from `api/openapi.yaml` with `openapi-typescript` into `ui/src/api/schema.gen.ts` (checked in, with a script `npm run gen:api` and a Bazel or CI test that fails when the checked-in file differs from a fresh generation). A thin `ui/src/api/client.ts`: same-origin `fetch` with `credentials: "same-origin"` (or `include` when `VITE_API_BASE` points elsewhere for development: UI-4), JSON, the `X-CSRF-Token` header on state-changing calls taken from the session response, and typed errors `{code, message}`; 401 anywhere sends the user to `/login`.
- Session-driven shell (UI-5, AUTH-5): on load call `GET /api/v1/session`. No session -> `/login`. Session with empty roles -> `/unauthorized` only, whatever URL was requested. `must_change_password` -> a change-password screen and nothing else. Otherwise the app layout: top bar with product name, navigation (My usage `/`, Setups `/setups`, and for admins Users `/admin/users` with the pending count badge, Setup inventory `/admin/setups`, Settings `/admin/settings`, Audit log `/admin/audit`), the signed-in user, their balance (hidden for the local admin), and the lab pressure pill with the current multiplier, exactly as docs/ui-notes.md "Shared" describes. Admin entries are not rendered for non-admins (the API enforces; the UI only reflects).
- Live numbers refresh every 60 seconds (UI-6): a `usePolling(fn, 60000)` hook that pauses when the tab is hidden and refetches on focus; the top bar uses it for `/me` and `/pressure`.
- Pages implemented in this task: `/login` (SSO button shown only when `auth/methods` says OIDC is available, linking to `/auth/oidc/start`; local admin username and password form; error display from `?error=`), `/unauthorized` (the exact sentence "You are not authorized to use Hourglass. Reach out to your admin.", the signed-in email, a sign-out link), the change-password screen (12-character minimum, shown errors), and a not-found route. The six role pages exist as placeholder components in `ui/src/pages/<name>/index.tsx` (`usage`, `setups`, `admin-users`, `admin-setups`, `admin-settings`, `admin-audit`), already routed and lazy-loaded, each rendering only its title.
- Shared components the page tasks will need, built now with tests: Button, Table (with empty state), Badge/Pill, Modal/ConfirmDialog, Form field with error, Toast or inline alert, token amount formatter (`formatTokens`), duration and date formatters, a `useApi` hook with loading/error states. No business logic: nothing here computes a balance, a cost or a projection (UI-1).
- Accessibility basics: real buttons/links/labels, focus management in dialogs, sufficient contrast per the tokens.
- No dependency of any Go code on this directory (UI-7). Every source file starts with the SPDX line (`// SPDX-License-Identifier: MIT`, or `/* ... */` for CSS, `<!-- ... -->` after the doctype for HTML); make `tools/check_spdx.sh` cover `ui/` sources while skipping `node_modules`, `dist` and generated/lock files.
- `ci.sh`: nothing new needed if Bazel covers build, tests, typecheck and the generated-client drift check.
## Tests
Shell routing by session state (no session, no roles, developer, admin, must-change-password), admin nav hidden for developers, CSRF header sent on POST, 401 redirect, polling hook with fake timers, formatters, login page variants, unauthorized page text exact.
## Scope
May write: `ui/`, `MODULE.bazel`, `MODULE.bazel.lock`, `.bazelignore`, `.bazelrc` (only if rules_js needs a flag), `.gitignore`, `tools/check_spdx.sh`, root `BUILD.bazel` (only gazelle excludes / npm link targets), this task folder. Do not touch Go code. Other agents are editing Go packages concurrently; Bazel commands queue.
## Long-running steps
First rules_js fetch and Vite build under Bazel: allow 20 minutes. `npx pnpm install` to create the lockfile: allow 5 minutes.
## Done when
`bazel build //ui/...` and `bazel test //ui/...` pass, `./tools/check_spdx.sh` passes, and RESULT.md documents versions, the directory layout, how a page task adds a page, the shared components' props, and how to run the dev server against a local `hourglassd`.
