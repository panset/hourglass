Job intent: .orchestrator/hourglass-v1/INTENT.md (read it first). Rules: .orchestrator/hourglass-v1/CONTRACT.md.
## Goal
Add a store-backed `Service` to `internal/ledger` (new files; the existing pure functions stay as they are) that performs every ledger write in Hourglass, so balance rules and balance events live in one place. ## Behaviour
`NewService(store, emitter, clock, loc *time.Location)`; `emitter` is an interface with `Emit(hourglass.Event)` (satisfied by the events dispatcher).
- `CurrentPeriod()`.
- `DebitTx(tx, userID, holdID, amountMT, at) (crossings, error)`: for the collector, inside its transaction; appends the debit to the current period and returns which thresholds were crossed. Events are NOT emitted inside a transaction: every method that runs in a caller's Tx returns the events to emit, and the caller emits them after commit; methods that own their transaction emit after commit themselves.
- `Grant(ctx, actorID, userID, amountMT, reason)` (LED-4) and `Reset(ctx, actorID, userID, reason)` (LED-5, to the current default allowance from settings): write the entry and an audit-log row in one transaction; return the entry. Rejected for the local admin account (it has no balance) and for users with no role.
- `EnsureFirstAllowanceTx(tx, userID, at)`: called when a user is first given a role; writes the allowance entry for the current period unless one exists (at most once per period); no-op for the local admin.
- `RolloverDue(ctx) (closed []string, err error)` (LED-3): determines the last opened period from the newest `allowance` entry period in the ledger (no extra state), and for each period boundary passed since then, in order, in one transaction per period: for every user who has at least one role and is not the local admin, write expiry or carryover and the new allowance (allowance amount = the default allowance setting at the time of the rollover), so the balance cache ends equal to the new period's sum; then emit `period.closed` with data `{"period": old, "next": new, "users": n}`. Idempotent: running twice writes nothing the second time; a crash between periods resumes correctly. With an empty ledger (fresh install) nothing is closed.
- `Balance(ctx, userID)` current-period balance; `MonthToDateBurn(ctx, userID)` sum of debits this period; `BurnLast24h`.
- Balance events: on any write that changes a balance, apply `Crossings` and emit `balance.low` / `balance.overdrawn` with the user and `{"balance_tokens": ..., "allowance_tokens": ...}`.
## Tests
Rollover with positive, zero and negative closing balances (spec example -40 -> 260); two skipped months; idempotence; user without a role skipped; local admin skipped; allowance change applies from the next rollover; first allowance once per period; grant/reset rules and audit rows; reset clears carried debt to exactly the allowance; crossings emitted once; timezone boundary with a non-UTC location.
