# 21a application wiring: config, Run, router skeleton, hourglassd
Job intent: .orchestrator/hourglass-v1/INTENT.md (read it first). Rules: .orchestrator/hourglass-v1/CONTRACT.md.
## Goal
A running `hourglassd`: config loading, the public `hourglass.Run`, the HTTP router with every route of `api/openapi.yaml` registered behind the right middleware, and the handlers that need no business logic. The remaining handlers are filled in by two later tasks working in parallel, so the structure you leave must let them work in separate files without touching yours.
## Context
Read the RESULT.md of tasks 08-store, 09b-fix-store, 10-extension-api, 16-events, 16b-settings, 17b-ledger-service, 17-collector, 17c-holds, 19-openapi and 20-auth (its "how to mount" section), then `api/openapi.yaml`. Spec: docs/SPEC.md "Architecture", "Configuration", "HTTP API", EXT-2, EXT-4, SET-7, AUTH-4, UI-3 (static serving itself is a later task), "Non-functional requirements" (JSON logs, metrics listener off by default).
## Contents
1. `internal/config`: load a YAML file (path from `-config` flag or `HOURGLASS_CONFIG`; a missing path means defaults + env only) into a typed struct: `listen` (default `:8080`), `database` (default `hourglass.db`), `session_key`, `timezone` (default `UTC`), `admin_password`, `oidc {issuer, client_id, client_secret, redirect_url}`, `provider {type, config}` (optional), `pressure {type, config}`, `metering {type, config}`, `hooks [{type, config}]`, `seed` (path, optional), `ui {serve: true}`, `cors {allowed_origins: []}`, `metrics {listen: ""}`. Environment variables override the file: `HOURGLASS_LISTEN`, `HOURGLASS_DATABASE`, `HOURGLASS_SESSION_KEY`, `HOURGLASS_TIMEZONE`, `HOURGLASS_ADMIN_PASSWORD`, `HOURGLASS_OIDC_ISSUER`, `HOURGLASS_OIDC_CLIENT_ID`, `HOURGLASS_OIDC_CLIENT_SECRET`, `HOURGLASS_OIDC_REDIRECT_URL`, `HOURGLASS_UI_SERVE`, `HOURGLASS_CORS_ALLOWED_ORIGINS` (comma-separated), `HOURGLASS_METRICS_LISTEN`. Each extension's `config` block is opaque: convert that YAML subtree to JSON (`json.RawMessage`) and hand it to the factory untouched. Unknown top-level keys are an error. A `Redacted()` view for logging that never contains secrets. The core names no concrete extension: the default pressure source and metering policy names are parameters supplied by the caller of `Run` (see 3).
2. Seed import (SET-7): if the database has no setups at start and `seed` names a file, import its setups (name, labels, details, enabled, resource_name_override) and rate rules (ordered selector + weight) and optional default weight in one transaction, validating like the admin API would; never applied again once any setup exists. YAML or JSON by extension.
3. `pkg/hourglass`: `func Run(ctx context.Context, opts Options) error` and `type Options struct { ConfigPath string; DefaultPressureSource, DefaultMeteringPolicy string; Args []string; Stdout, Stderr io.Writer; UI fs.FS (nil = no UI) }`. Run: load config; set up `slog` JSON logging; open the store (migrations); `EnsureLocalAdmin`; build the provider (if configured), pressure source, policy and hooks through the registry, failing startup on an unknown name with the registry's error listing the registered names (EXT-2); import the seed; start the events dispatcher, the collector loop and the HTTP server; serve until ctx is cancelled, then shut down in order (HTTP, collector, events, store) with a 10-second bound. `pkg/hourglass` may import `internal/...` for this; put the bulk in `internal/app` so the public package stays thin. To avoid an import cycle, internal packages keep importing `pkg/hourglass` for types, and `Run` lives in a file that delegates through a function variable set by `internal/app` (or an equivalent cycle-free arrangement; explain what you chose).
4. `cmd/hourglassd/main.go`: blank-imports the bundled extensions that exist today (`pressure/inventory`, `policies/default`, `providers/static`, `hooks/webhook`), calls `hourglass.Run` with defaults `inventory` and `default`, handles SIGINT/SIGTERM. `hourglassd version` prints the version. (A `check-provider` subcommand and the vsphere import are added by a later task; leave a clear place for subcommands.)
5. `internal/api`: `New(Deps) http.Handler` using the stdlib `http.ServeMux` with method patterns. One exported route table (`Routes() []Route{Method, Pattern, Access, OperationID}`) that is the single source for registration and for the future contract test. Middleware chain per access level from `internal/auth`: public; session; role; admin; local-admin; CSRF on every state-changing route; the forced-password-change guard; CORS; a panic recoverer returning the standard `internal` error; request logging without bodies, cookies or tokens; `Cache-Control: no-store` on all API responses. Anything not matching a registered route under `/api/` or `/auth/` returns the JSON `not_found` error (never HTML); other unknown paths go to an optional fallback handler (the UI, later) or 404.
   Implement here: `GET /healthz` (database reachable, age of the last successful poll, 200/503), `GET /api/v1/auth/methods`, `GET /api/v1/session`, and mount the `/auth/*` handlers.
   For every other operation in `api/openapi.yaml`, create the handler method as a stub returning 501 `not_implemented`, placed in exactly two files so the next tasks do not collide: `handlers_user.go` (me, me/holds, me/ledger, me/usage, pressure, setups list, acquire, release) and `handlers_admin.go` (admin users, roles, reject, grants, reset, admin setups, rules, settings, collector, audit). Shared helpers (JSON decode with size limit and unknown-field rejection, JSON encode, id/period parsing, milli-token to tokens conversion, mapping of `holds`/`ledger`/`settings` typed errors to error codes and statuses per the OpenAPI error table) go in `helpers.go`, with tests.
6. Metrics: when `metrics.listen` is set, a second listener serving Prometheus text format at `/metrics` with poll duration, poll failures, lab pressure and tokens debited, written by hand in the text exposition format (no new dependency); never on the public port. Off by default.
7. One new store method if needed for `last_login_at` of the local admin, in a new file `internal/store/app_queries.go` with a test; call it from wherever is least invasive without modifying `internal/auth` beyond a one-line hook if unavoidable (say so).

## Tests
Config: file + env override, opaque block passthrough, unknown key, redaction. Seed: applied once, skipped when setups exist, invalid seed rejected atomically. Run: starts on a temp database with no provider and no OIDC (EXT-4), serves `/healthz`, shuts down cleanly on cancel; unknown extension name fails with the list of registered names. Router: every route in the table answers something other than 404; unknown `/api/v1/x` gives JSON `not_found`; `auth/methods` and `session` shapes match the OpenAPI schemas; an unassigned user's session response has an empty role list; middleware order (401 before 403, CSRF checked on POST). Names cite requirement ids.
