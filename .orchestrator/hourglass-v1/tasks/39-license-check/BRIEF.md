# 39 dependency license check in CI
Job intent: .orchestrator/hourglass-v1/INTENT.md (read it first). Rules: .orchestrator/hourglass-v1/CONTRACT.md.
## Goal
CI fails on any dependency whose license is not permissive. Spec: docs/SPEC.md "License": "CI runs a license check on dependencies and fails on anything that is not permissive (MIT, BSD, Apache-2.0, ISC)."
## Requirements
- `tools/check_licenses.sh`, called from `ci.sh`, covering (a) every Go module in the build list of the main module (`go list -m all` restricted to modules actually needed to build: use `go list -deps -f` on `./...` to find the modules in use, test dependencies included), reading each module's LICENSE/COPYING file from the module cache and classifying it, and (b) every npm package in `ui/pnpm-lock.yaml` that ships in the production bundle or is used to build and test (classify from each package's `license` field; a script may read `node_modules` if present, otherwise the registry metadata recorded in the lockfile; if neither is available offline, say what is needed), and `e2e/browser` if it exists.
- Allowed: MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, ISC, and the equally permissive 0BSD, Unlicense, CC0-1.0, BlueOak-1.0.0, Python-2.0 only if they actually occur (list each such exception explicitly in an allowlist file `tools/licenses_allow.txt` with a one-line justification; anything else fails). MPL-2.0, LGPL, GPL, AGPL, SSPL, BUSL, unknown or missing licenses fail, naming the module.
- No new tool dependency that itself needs a network install at CI time: plain shell plus `go` and `node` already in the toolchain. Classification by recognisable license text/SPDX markers is acceptable; unknown text fails closed.
- Must work on macOS and Linux and run in well under a minute.
- Write the current inventory to `docs/third-party-licenses.md` (module, version, license), generated by the script with a `--write` flag, and have the check fail if that file is out of date.
- If a current dependency fails the policy, do not remove or replace it: report it as an open question with the dependency path that pulls it in.
## Scope
May write: `tools/check_licenses.sh`, `tools/licenses_allow.txt`, `ci.sh` (one line), `docs/third-party-licenses.md`, this task folder. Other agents are editing go.mod and MODULE.bazel concurrently (new test dependency kin-openapi, rules_oci): the inventory may need regenerating after they finish; say so in RESULT.md. Do not run Bazel.
## Done when
The script passes on the current tree, fails on a seeded disallowed license (prove with a temporary fake entry, then remove it), and RESULT.md lists the license mix found.
