# 29 verify UI: RESULT

Status: done. Verdict: PASS WITH FINDINGS. The UI follows the spec and the wireframes closely, holds no meaningful business logic, uses only the generated-types client, and all behaviours in the "Behaviour worth pinning down" list work in a real browser. No HIGH findings. Two MEDIUM (blank page on a failed lazy chunk; focus not moved to opened side panels) and a handful of LOW.

Run: clone at scratchpad/verify-29/hourglass (commit 160bdc6), bundled binary built with Bazel, run on 127.0.0.1:18080 (and 18081 for the empty-database run), static provider, inventory pressure, throwaway admin password. Browser: system Google Chrome via Playwright 1.65 (the Playwright Chromium download did not finish, contended with another agent's installer). Developer, admin and no-role users were created by inserting rows and session rows directly into SQLite (the API cannot create OIDC users); acquires went through the real API. Screenshots: `screens/` (about 3.4 MB).

## Findings

1. MEDIUM, all pages, `ui/src/main.tsx:9-13`, `ui/src/shell/Layout.tsx:15-25`. Spec: UI-1/robustness (an API or network failure shows an error state, not a blank page). There is no error boundary. Pages are lazy-loaded; if the page chunk cannot be fetched (server down before the page was first visited, or a stale hashed `/assets/*.js` after a redeploy in a long-open tab) React unmounts the whole app: blank white page, empty `<body>` text (reproduced; `screens/server-down-after-nav.png` is blank). When chunks were already loaded, every page showed "Cannot reach the server." with Retry (good). Fix: add an ErrorBoundary around `<Suspense>` with a "reload the page" message.
2. MEDIUM, Users and Setup inventory, `ui/src/pages/admin-users/index.tsx:305-317`, `ui/src/pages/admin-setups/index.tsx:166-177`. Keyboard-only: pressing Grant or Edit opens the side panel but focus stays on the button, and the panel is after the table in DOM order. With 209 users the keyboard user must tab through every remaining row to reach "Amount". Observed: first Tab after Grant lands on the next row's role checkbox. Fix: move focus to the panel heading/first field when it opens, return it on Cancel.
3. LOW, My usage / Ledger, `ui/src/lib/format.ts:44` (formatDateTime uses the browser zone) vs `ui/src/pages/usage/index.tsx:250-252` (axis labels forced to UTC). Ledger times and the bar-chart dates use different zones. In a UTC-7 browser the 1 Nov 00:00Z allowance row shows "Oct 31, 17:00" inside the November ledger. Fix: format with the deployment timezone (or UTC) consistently, ideally from an API field.
4. LOW, UI-1 (see audit below): held-for and "Free for X more" are computed in the browser from timestamps; password minimum 12 duplicated.
5. LOW, Setups and Setup inventory layout. `screens/dana-setups.png`: setup names wrap at the hyphen ("setup-" / "01") and headers wrap, because the Cost and action columns take the width. `screens/riley-edit-setup.png`: with the Edit panel open the list is clipped and the "Disable" button is cut off at the right edge. Settings rate-rule row actions (Up/Down/Remove) wrap into two lines. Fix: `white-space: nowrap` on the name column, allow the two-column layout to stack below about 1400 px.
6. LOW, narrow screens (390 px): `/setups`, `/` and `/admin/users` overflow the document horizontally (scrollWidth 873, 518, 847). The wireframes are 1280 px, so this is outside the wireframes; tables are in scrollers but the page itself still overflows (probably the cards/title rows).
7. LOW, `ui/src/shell/session.tsx:26-31`. A network error (not only a 401) on the initial `GET /session` is treated as "signed out", so a server blip on page load shows the sign-in page instead of an error with Retry. Same code path swallows every `getSession` failure.
8. LOW, polling cost, `ui/src/shell/TopBar.tsx:16-18` plus each page (`usage/index.tsx:60-63`, `setups/index.tsx:58-61`, admin pages). Top bar and page each poll `/pressure`, `/me`, `/admin/users` on their own 60 s timers: two requests per tick (measured 2 then 4 `/pressure` requests across the first 61 s with a fake clock). Interval is correct (60 s); only duplicated. Fix: share one polled store.
9. LOW, Acquire dialog (`ui/src/pages/setups/index.tsx:290-309`, `components/Modal.tsx`). Initial focus is the primary "Acquire" button, so a stray Enter acquires. Focus trap, Escape and focus return are correct. The "This will be your Nth of M allowed setups" and charging-start sentence are absent (the latter only appears when the API's `metering_description` is non-null; it was null with the default policy). Spec does not require either.
10. LOW, Users page controls differ from the wireframe: roles are two checkboxes plus a "Save roles" button (wireframe: a select with Unassigned/Developer/Admin and "Choose role"); Approve is disabled until a role is ticked; pending requests are cards, not a table with columns User / First signed in / Assign role. Spec says "roles" (plural) so checkboxes are defensible. The grant button reads "Grant tokens" (wireframe "Grant 100 tokens"); the live "New balance" line is correctly absent (it would be business logic).
11. LOW, Settings: pressure bands are edited as fractions 0 to 1 plus a separate "Base multiplier" (wireframe: percentages, rows 0%/50%/75%/90%); "Poll interval" takes a duration string like `5m` (wireframe: "Poll interval (minutes)"). Extra, not in wireframe or spec: "Event queue" card, Outage history table, Recent failed event deliveries table.
12. LOW, UI-7, `internal/uiserve/uiserve.go:28`. The Go server hard-codes the `assets/` prefix for immutable caching, a Vite layout detail. It is the only coupling found; no Go file mentions React, routes or the UI source layout (grep). Acceptable under "one static directory" but a different UI would need to use that prefix or lose long caching.
13. INFO: anonymous page loads log one expected 401 from `GET /api/v1/session` in the console. No CSP violations, no other console errors, nothing external.
14. INFO (task hygiene): another agent's `pkill hourglassd`-style command stopped my first two server instances (log shows SIGTERM shutdowns I did not send); I renamed my binary and was not affected afterwards. I also ran one `pkill -f "hourglassd -config"` early, which may have stopped another agent's `hourglassd` (verify-23) at about 08:42 local; that process was alive when I looked a minute later, but I cannot rule out a brief interruption.

- `ui/src/pages/setups/index.tsx:113-119`: "Free for X more" = `metering.expected_start_at` minus now, and the branch choice `start > Date.now()`. API provides `expected_start_at` and a `reason`, no remaining-duration field. Display only; LOW.
- `ui/src/pages/setups/index.tsx:22-26` `stateOf`: derives Free/Deployed/Acquired/Disabled from `state` plus `deployed` for the state filter. API fields exist for each; client-side filtering of a fetched list is allowed. OK.

- `ui/src/pages/admin-users/index.tsx:109` zero-amount grant check, `admin-settings/form.ts:40-77` number parsing: form validation only.
- `usage/BarChart.tsx:11-18`, `usage/PressureBar.tsx:15-52`: scale bars and band widths from API values; presentation only. `format.ts` rounding/percent/duration: formatting only.
