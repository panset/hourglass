2. Page by page (Sign in, Not authorized, change password, My usage, Setups, Users, Setup inventory, Settings, Audit log): compare the running page and its source with docs/ui-notes.md: regions, table column headers and their order, button and field labels verbatim, badges and states, dialogs, navigation, top bar (user, balance, pressure pill with multiplier), admin-only navigation with the pending count. 5. UI-2/UI-5: every network call goes through the generated-types client; no hand-typed response shapes that diverge from `schema.gen.ts`; the drift test really fails when the YAML changes (change a field in the clone and run it); the UI never stores tokens; nothing sensitive in localStorage/sessionStorage; role-based rendering comes only from the session response.

7. Robustness in the browser: every page with an empty database (no setups, no users besides admin); API error (stop the server mid-session) shows an error state rather than a blank page; a 401 mid-session returns to sign-in; long names, many labels, 100 setups and 200 users (seed them) render without layout breakage; keyboard-only operation of the acquire dialog and a form; visible focus; labels on inputs; colour contrast of text against the tokens in ui-notes.md (compute a few).
8. Dependencies: list the runtime dependencies in `ui/package.json` and confirm nothing loads from another origin at runtime (inspect the built `index.html` and network requests in the browser run).
