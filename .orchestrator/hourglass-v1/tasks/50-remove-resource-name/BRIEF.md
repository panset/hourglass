# 50 remove the resource-name template and override from the core; move naming into the provider
Job intent: .orchestrator/hourglass-v1/INTENT.md. Rules: .orchestrator/hourglass-v1/CONTRACT.md (if `.md` files cannot be written, use `.txt` and put the result in your reply).
## Why
The owner has changed the spec: Hourglass is a generic framework, and the "resource name template" (SET-4) is a leftover of the earlier vSphere-specific design. Decision D40 in docs/decisions.md is the new contract for this area and overrides SET-4, the SET-4 parts of ADM-2, the Configuration row "Resource name template", the "resource name" items in the Dashboard pages table, and decisions D32/D33's template parts. Everything else in docs/SPEC.md still holds. Do not edit docs/SPEC.md.
## Target behaviour
- Core matching rule: an allocation reported by the resource provider belongs to the setup whose **name equals** the allocation's `ResourceName`. Nothing else. An allocation whose name equals an enabled or disabled setup with no active hold is an orphan (HOLD-4, unchanged); a name matching no setup is ignored.
- Removed from the core everywhere: the `resource_name_template` setting (code, defaults, validation, JSON form, the template sandbox and its tests, the stored settings key: an existing stored key is ignored and deleted by the migration below), the per-setup `resource_name_override` (store column via a NEW numbered migration that drops it; never edit an old migration; make sure a database created by the previous commit upgrades and that the setups table keeps its data), `settings.ResourceName`, any "expected resource name" field on the public `hourglass.SetupState`/`Snapshot` types (this is a breaking change to the public extension API and is intended; keep `Snapshot.AllocationFor(setupName)`), the `resource_name` and `resource_name_override` fields in `api/openapi.yaml`, handlers, seed file format (a seed that still contains `resource_name_override` is rejected with a clear message), the generated UI schema, the Settings page field, the setup form's override field and the inventory's resource-name column, `check-provider` output wording (it now prints setup names), audit before/after shapes, docs, examples and tests.
- `providers/vsphere`: new optional config keys `pool_name_prefix` and `pool_name_suffix` (strings, default empty). When either is set, the provider reports only resource pools whose name has that prefix and suffix, with both stripped from `ResourceName` (so pool `lab-06_RP` with suffix `_RP` is reported as `lab-06`); pools that do not match are not reported at all; a pool whose name is exactly the prefix plus suffix (empty remainder) is skipped. With both empty, every pool is reported under its own name, as today. The original pool name stays available in the allocation's labels (`pool`). Unit tests at layer 2 (fake) and one at layer 3 (simulator). Unknown config fields are still rejected.
- Reference scenario: `deploy/config.sample.yaml` sets `pool_name_suffix: _RP` in the vsphere provider block (the pressure source shares the connection block; it must accept and ignore these two keys, or the sample must give each block only its own keys: choose the simpler and say which). `deploy/README.md`, README.md, docs/deploying.md, docs/extending.md, CONTRIBUTING.md and `deploy/seed.sample.yaml` comments: remove every mention of the template and of setting it at first run (the display label key `size` is still a first-run admin step).
- `examples/custom`: adapt to the API change; its README should show a provider doing its own name mapping in one sentence.
- End-to-end test (`e2e/browser/tests/acceptance.spec.ts`): step A0 no longer sets a template; the rest is unchanged (the test still creates pool `<setup>_RP` in the simulator). `deploy/smoke.sh` likewise.
- Core genericity: after this change no core package may contain a naming rule of any kind; `tools/check_core_generic.sh` gains the terms `_RP` and `resource_name_template` for core files (tests included: use neutral names in core tests).
- Requirement ids in tests: tests that cited SET-4 are removed or renamed to cite the rule they still cover (HOLD-4, MET-2) and `D40` in a comment.
## Out of scope
